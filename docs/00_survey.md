### 트랙 좌표 (섹터 헤더 MSF 로 **실측**)

- track1 : LBA `0` .. `449`
- track3 : LBA `45000` .. `139653` — **ISO9660 PVD 는 여기(LBA 45016)**
- track4 : LBA `139654` .. `140482` (AUDIO)
- track5 : LBA `140708` .. `549149` — 파일 선두 **225섹터는 pregap**(mode 0)

⚠️ **파일시스템은 track3 에 있으나 대부분의 파일 실체는 track5 에 있다.**
LBA→트랙 매핑 없이 track3 만 읽으면 거의 모든 파일을 못 읽는다. `tools/gdi.py` 의
`Disc.read(lba, n)` 가 이 매핑을 담당한다.

- 볼륨 ID `ASUKA_KENZAN`, 볼륨 크기 504,150섹터, 파일 241개
- IP.BIN: `SEGA SEGAKATANA` / `HDR-0187` / `V1.00620020117` / 부트 바이너리 **`1NOSDC.BIN`**
- ⏳ **미확정**: `DUMMY.TXT`(LBA 139503)·`WARNING.DA`(LBA 139804, 1,390,592B)는 track4(AUDIO)
  구간에 걸쳐 있다. 실제 읽기 방식 미확인 — 수정 대상이 아니면 건드리지 않는다.

## 2. 현지화 대상 — 저장 위치 (확정)

문자열은 **평문 Shift-JIS, NUL 종단, 개행 = 0x0A**. 압축 없음(엔트로피 4.2~5.8).

| 파일 | 크기 | 성격 | 문자열 | 글자수 |
|---|---|---|---|---|
| `DATASCR.BIN` | 882,688 | **본편 스크립트**(VM 바이트코드 + 인라인 문자열) | 7,174 | **185,700** |
| `SSCR.BIN` | 809,344 | **시스템·아이템 설명·안내문** | 4,986 | **84,991** |
| `1NOSDC.BIN` | 1,941,796 | 실행 파일 내 UI 라벨 | 4,632 | 12,522 |

합계 **≈283,000자 (하한)**. 노이즈 제거는 [[feedback_font_filter_kills_fake_text]] 기법 —
「폰트 레퍼토리(2,472+ANK)에 없는 글자가 든 문자열은 가짜」 — 을 적용했다.
그래픽 컨테이너(`DATAMAS/DATABG/DATAIDA/DATASZU/DATADAI`)는 이 필터로 99% 걸러졌다.

⏳ **미확정**: (a) `1NOSDC.BIN` 4,632건에는 아직 노이즈가 섞여 있다(2글자짜리 한자쌍 등).
(b) 스크립트 VM 의 문자열 경계·제어코드·길이 예산은 미규명 — 소비 코드로 확정해야 한다.
(c) `DATAFIX.MAP`(131MB)·`DATASHF.MAP`(472MB)·`DATAOBJ.BIN`(54MB)·`DATANAS/RND`·`TEST.MAP`
미조사. (d) 그래픽에 구운 텍스트 모집단 미조사.

## 3. 폰트 — **전량 규명 완료** (`DATAAPP.BIN`)

`DATAAPP.BIN`(612,352B) = 앞부분 사운드 드라이버(`SDRV`/manatee.drv) + **뒷부분 폰트 일체**.

자산 청크 헤더(16B) + 태그(16B):
`u32 청크총크기 | u32 포맷 | u16 width | u16 height | u32 0 | char[16] 태그`

| 오프셋 | 태그 | 크기 | 내용 |
|---|---|---|---|
| 0x09000 | `font1000` | 512×512 4bpp | **페이지 0 + 1** |
| 0x29020 | `font1001` | 512×512 4bpp | **페이지 2 + 3** |
| 0x49040 | `font1002` | 512×512 4bpp | **페이지 4 + 5** |
| 0x69060 | `font1003` | 512×512 4bpp | **페이지 6** (상위 플레인 비어 있음) |
| 0x89800 | — | 4,944B | **전각 폭 테이블** (글리프당 `u8 left, u8 right`) |
| 0x8b000 | — | 4,944B | **전각 문자표** (SJIS 2바이트 × **2,472자**, 50음순) |
| 0x8c800 | `fontanc000` | 128×128 4bpp | 반각 A |
| 0x8f000 / 0x8f800 | — | 256B / 256B | 반각 A 폭표 / 문자표(`A B C …`) |
| 0x90000 | `fontank000` | 128×128 4bpp | 반각 B |
| 0x92020 | `fontank001` | 128×128 4bpp | 반각 C |
| 0x94800 / 0x95000 | — | 512B / 256B | 반각 B/C 폭표 / 문자표(`! " # …`) |

### ★★핵심 구조 — 4bpp 텍스처 한 장에 **2bpp 폰트 두 페이지**가 겹쳐 있다

- 텍스처는 **트위들(모튼) 배치**이며 **x/y 비트가 뒤바뀐** 변형이다.
  `n |= ((y>>b)&1)<<(2b); n |= ((x>>b)&1)<<(2b+1)` 로 풀어야 글자가 나온다.
- 각 픽셀의 **하위 2비트 = 짝수 페이지, 상위 2비트 = 홀수 페이지**.
  (증거: `font1003` 은 니블 값이 0~3 뿐 — 마지막 페이지라 상위 플레인이 비었다.)
- 글리프 격자 **피치 26px**, 사용 영역 494×494 → **19열 × 19행 = 페이지당 361자**.
  (실측: 빈 열/행이 494~511 뿐, 열 자기상관 최대 주기 26)
- 7페이지 × 361 = 2,527칸, 문자표는 2,472자 → **여유 55칸**.
- 페이지 선두 글자로 매핑 검산 완료:
  p0=`　、。・：`(idx0) / p1=`駅`(361) / p2=`靴`(722) / p3=`芝`(1083) /
  p4=`蘇`(1444) / p5=`童`(1805) / p6=`貌`(2166)
- **가변폭(VWF)**: 폭표의 한자는 대부분 `(0,25)`(26px 꽉 참), 약물은 `(1,9)` 등으로 좁다.

## 4. 한글화 예산 — 1차 판정

- 전각 슬롯 **2,472 + 여유 55**. [[feedback_jp_kr_overwrite_all_slots]] 대로 가나·한자 칸은
  **전부 자원**이다. 여기서 ASCII·숫자·약물용을 빼도 **≈2,300칸 이상**이 한글 음절에 쓸 수 있다.
- 일반적인 게임 스크립트의 고유 한글 음절 수는 1,200~1,800자 → **통글자 배정으로 커버 가능**할 것으로 보이나
  **실제 번역 코퍼스로 재측정해야 확정**이다.
- 부족하면 대안은 [[reference_johab_font_builder]] 조합형(부품 210개) — 다만 이 폰트는 VWF 이므로
  «전진폭 0» 부품을 그리는 방법을 렌더러에서 먼저 확인해야 한다.

- `tools/gdi.py` — 트랙 좌표 매핑, LBA→user 2048B 판독
